# Harvest 04 — behaviour in the old code that the concept may not have

The owner asked for the **previous implementation** to be read as evidence of what the product
actually did — *finer points we may not have covered, because I simply forgot them* — and warned
that a good deal of it is **not considered design**: the previous round spiralled, and much of the
code works around a limitation of how it was built rather than serving anyone.

**Nothing here is adopted.** Per [PR-1](../../../CLAUDE.md) legacy is quoted, never inherited; per
[D-003](../90-decision-log.md) content leaves it only through a reviewed sheet. This sheet produces
rows, not concept text. No concept document, decision log entry or line of `includes/`, `src/` or
`docs/legacy/` was touched.

Every **missing** row below was checked against all 264 entries of
[the decision log](../90-decision-log.md) before being written down.

## What was read

`wp-taxonomy-tree.php` · all 39 files under `includes/` · both blocks and the shared editor
components under `src/` · `assets/js/` (tree admin, node picker, converter, validator, sample data,
media render) · `scripts/` including `scripts/windows/` · `prototypes/tree-split/` ·
`webpack.config.js` · `package.json`.

**Not repeated here:** the standard tree fixture ([harvest 01](01-standard-tree.md)) and the admin
menu and settings screen ([harvest 02](02-settings-page.md)). Where the code does something those
sheets do not mention, it is a row below — including **answers to three of the open questions
sheet 02 ends with** (`Cleanup`, `Fill Model Data`, `node_presentation`), which the code settles.

## Contradicts

| Finding | Where in the code | Verdict | Detail |
|---|---|---|---|
| **Names are enforced unique in two places.** *"Data type name “%s” is already used by another sibling node. Instance nodes may reuse names across parents; siblings should not."* and *"An attribute with this name already exists on this node."* There is even a repair script to find and merge same-name siblings. | `includes/class-node-type.php`, `includes/class-attribute.php`, `scripts/scan-duplicate-siblings.php` | **contradicts** | [D-022](../90-decision-log.md) and [C21](../10-domain-core.md): *a node name is required and explicitly **not** unique; two different nodes may each have a child of the same name*, and the sibling-uniqueness idea is named there and rejected. ⚠️ Worth knowing **why** the old code did it: `scan-duplicate-siblings.php --fix` exists because the tree kept acquiring duplicate siblings during the spirals. That is an argument for a **duplicate warning**, not for a rule — and [D-114](../90-decision-log.md) already has the shape (identifying fields warn, `unique` refuses). |
| **A new node's icon is looked up in a hard-coded map keyed on its display name** — `int`/`integer`/`double` → calculator, `bool` → yes, `date` → calendar, `display_node_name` → tag. | `Tree_Icons::standard_for_name()` | **contradicts** | [D-055](../90-decision-log.md) — *data reference node ids, never names* — and `CLAUDE.md`'s outright prohibition on **special-casing by display name**. Rename `int` to `Ganzzahl` and the behaviour vanishes; in the German tree it never fired at all. The underlying need — *a new node should not arrive blank* — is legitimate and belongs on the **type node** as a resolved setting ([D-019](../90-decision-log.md)), which costs nothing extra. |
| **A new child copies its parent's icon once, at creation; later changes to the parent do not cascade.** *"On create: standard icon by term name first; else copy parent icon when set. Later parent edits do not cascade. No live father-walk at render time."* | `includes/class-tree-icons.php`, class docblock | **contradicts** | [D-019](../90-decision-log.md) puts `icon` in the settings table and resolves it through the **same walk** as every other setting; [D-015](../90-decision-log.md) says a change to a base setting **propagates live** to everything that has not overridden it. Copy-on-create is the opposite: it freezes, and it writes the same fact onto every descendant. The comment names the reason — *no live father-walk at render time* — which is a performance worry [D-014](../90-decision-log.md) already answers by loading the walk in one batched step. |
| **A media attribute ships accepting nothing.** The MIME allow-list defaults to **empty**, and the UI has to warn that the field will not work until a kind is ticked. | `Node_Type::META_KEY_MEDIA_ALLOWED_KINDS`, *"Default empty = none enabled"* | **contradicts** | [D-046](../90-decision-log.md) settles the default for exactly this shape of setting: **`all except {}`**, precisely so a newly added kind reaches existing attributes automatically and nothing is silently inert. [D-262](../90-decision-log.md) adds the tiebreaker — *of two possible defaults, take the one whose failure is noticed*. A field that does nothing is noticed; but D-046 already decided the direction, and the media setting was built the other way. |
| **A validator may be a free-typed boolean expression.** *"Use `value` in a boolean expression, e.g. `value >= 0 && value <= 100`"*, stored as a string on the node and evaluated in JavaScript. | `Validator::BUILTIN['expression']`, `assets/js/wtt-validator.js` | **contradicts** | [D-130](../90-decision-log.md): *the expression is a **structured tree**, built with a picker rather than typed*, from a small closed set of operations. A typed string is un-analysable — [D-045](../90-decision-log.md)'s dependency graph cannot be parsed out of it reliably, [D-062](../90-decision-log.md)'s transformations cannot be offered over it, and it is evaluated where the model cannot see it. Note that the same class also holds the good half: **`min` / `max` / length / charset as named validators with parameters**, which is what the structured form should produce. |
| **Sample values are chosen by matching the attribute's name against a keyword table** — `vorname`/`first name` → *Herbert*, `firma`/`company` → *Muster GmbH*, `einheit`/`unit` → *Ohm*, `telefon` → a phone number — before falling back to the type. | `Sample_Data::name_map()` | **contradicts** | The same prohibition as the icon row: [D-055](../90-decision-log.md), [D-022](../90-decision-log.md), and `CLAUDE.md`'s ban on special-casing by display name. It is bilingual by brute force (`vorname`, `first name`, `firstname`, `given name`, `surname`, …) which is what the mechanism costs. ⚠️ **The need it serves is real and is listed above as missing** — a preview that reads like a real record. The right place for it is a sample on the **type** ([D-240](../90-decision-log.md)) plus something that keeps a record's samples consistent, never a keyword table. |

## What this sheet is not

It adopts nothing and changes nothing. Per [D-003](../90-decision-log.md) and
[D-006](../90-decision-log.md), content leaves legacy only through an explicit decision per row.
The **missing** rows are the ones that need the owner; the **workaround** rows need only to be
recognised and never rebuilt.

⚠️ **One caveat on the whole reading.** The code is the state at the end of a round that the owner
describes as spiralling, with an assistant that hallucinated. Several files carry `Q<n>` markers
referring to a numbering scheme that no longer exists, and at least one construct (`set` / `table`)
was already half-retired inside the codebase itself. Where a behaviour is implemented but visibly
mid-retirement, that is said in the row rather than presented as a finding.
